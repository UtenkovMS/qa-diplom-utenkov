## Описание тестируемого приложения

Приложение - веб-сервис, который предлагает оплатить тур двумя способами:

1. По дебетовой карте, через сервис Payment Gate
2. По кредитной карте, через сервис Credit Gate.

Приложение имеет СУБД, которое сохраняет статус выполненной операции и способ выполнения платежа, и не сохраняет данные карт.

***

## Валидные данные для полей ввода тестируемого приложения

#### Поле "Номер карты":

Валидными данными считаются цифры от 0 до 9, длина поля 16 символов.

**Важно:** согласно условиям эмулятора банковского сервиса gate-simulator для покупки тура
по номеру карты: 

1. "4444 4444 4444 4441" - установлен статус "APPROVED" - "Одобренный"
2. "4444 4444 4444 4442" - установлен статус "DECLINED" - "Отклоненный"

#### Поле "Месяц":

Валидными данными считаются цифры от 0 до 9, длина поля 2 символа в формате "mm".
Граничные зачения: от 01 до 12 включительно.

#### Поле "Год":
Валидными данными считаются цифры от 0 до 9, длина поля 2 символа в формате "yy". 
Граничные значения: от 26 до 31 включительно.

#### Поле "Владелец":

Валдидными данными считаются латинские буквы, символ "-" и пробел.
Длина поля от 2 символов до 21 символа включительно, учитывая символ "-" и пробел.

#### Поле CVC/CVV:

Валидными данными считаются цифры от 0 до 9, длина поля 3 символа.
Граничные значения от 000 до 999.

## При выполнении дипломного проекта использовались инструменты:

**IntelliJ IDEA** - среда разработки, предназначенная специально для программирования на Java и многих других языках.
<br>**Java** - Один из самых популярных языков программирования, применяемый для широкого спектра задач, включая разработку приложений и автоматизацию тестирования.
<br>**Gradle** - Система сборки программного обеспечения. Gradle сочетает в себе возможности управления зависимостями, автоматического запуска тестов и генерации отчетов.
<br>**JUnit 5** - Фреймворк для модульного тестирования приложений. Позволяет быстро писать тесты с использованием удобных методов, классов и аннотаций.
<br>**Java Faker** - Библиотека для генерации случайных данных на Java. Позволяет заполнять тестовую базу случайными значениями (имена, телефоны, email и прочее), делая тесты реалистичными и разнообразными.
<br>**Lombok** - Аннотационная библиотека для Java, уменьшающая объём шаблонного кода, необходимого для создания классов, геттеров/сеттеров, конструкторов и других примитивных методов.
<br>**Allure** - библиотека для генерации наглядных отчетов по результатам выполнения тестов. Показывает статистику прохождения, графическое представление проблем и детальную информацию о сбоях.
<br>**Docker** - Программа для контейнеризации приложений. Она позволяет упаковать ПО вместе со всеми его зависимостями и настройками в контейнеры, а затем запустить их на любых машинах, вне зависимости от ОС и конфигурации среды.
<br>**Docker Compose** - Утилита для управления многоконтейнерными приложениями Docker, позволяющая описывать зависимости между контейнерами в едином файле.
<br>**DBeaver** - Графический клиент для работы с базами данных, который позволяет управлять СУБД из одного интерфейса. Поддерживает MySQL, PostgreSQL и другие.
<br>**Git и GitHub** - Система контроля версий, обеспечивающая возможность одновременной работы над проектом нескольким участникам. GitHub — облачный сервис для размещения и совместной работы с Git-проектами.
<br>**Git Bash** — приложение для сред Microsoft Windows, эмулирующее работу командной строки Git.
<br>**CI** облачного сервиса **GitHub** - инструмент позволяющий запусукать и логировать тесты на базе сервиса **GitHub**

## Запуск автотестов

1. Создать на ПК папку для клонирования дипломного проекта.
2. Открыть созданную папку программой **Git Bash** и ввести в терминале команду: git clone https://github.com/UtenkovMS/qa-diplom-utenkov.git . для клонирования репозитория в текущую папку проекта.
3. Запустить программы **Docker** и **IntelliJ IDEA**.
4. В программе **IntelliJ IDEA** в первом терминале ввести команду: docker compose up для запуска и сборки среды описанной в файле проекта docker-compose.yml
5. Во втором терминале запускаем приложение веб-сервиса покупки туров командой: java -jar ./artifacts/aqa-shop.jar
6. В браузере  **Google Chrome** проверяем, что веб-сервис доступен по ссылке: http://localhost:8080/
7. В третьем терминале запускаем автотесты для взаимодействия с СУБД MySQL командой: ./gradlew clean test поумолчанию команда использует переменную db.url настроенную на взаимодейтствие с MySQL.
8. Для запуска автотестов, взаимодействующих с PostgreSql, в третьем терминале вводим команду: ./gradlew test -Ddb.url=jdbc:postgresql://localhost:5432/app переопределяющую переменную db.url для работы с PostgreSql.
9. После выполнения тестов формируем отчетность, в третьем терминале вводим команду: ./gradlew allureServe
***

## Завершение работы со средой тестирования

1. Переходим во второй терминал и останавливаем работу тестируемого приложения командой: Ctr+C
2. Переходим в первый терминал и останавливаем работу контейнеров **Docker** командой: Ctr+C
3. В первом терминале вводим команду для удаления контейнеров **Docker**: docker-compose down
