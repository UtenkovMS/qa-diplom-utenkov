# План автоматизации тестирования

***

## Описание приложения

Приложение - веб-сервис, который предлагает оплатить тур двумя способами:

1. По дебетовой карте, через сервис Payment Gate
2. По кредитной карте, через сервис Credit Gate.

Приложение имеет СУБД, которое сохраняет статус выполненной операции 
и способ выполнения платежа, и не сохраняет данные карт.

***

## Валидные данные для полей ввода

#### Поле "Номер карты":

Валидными данными считаются цифры от 0 до 9, длина поля 16 символов.

**Важно:** согласно условиям эмулятора банковского сервиса gate-simulator для покупки тура
по номеру карты: 

1. "4444 4444 4444 4441" - установлен статус "APPROVED" - "Одобренный"
2. "4444 4444 4444 4442" - установлен статус "DECLINED" - "Отклоненный"

#### Поле "Месяц":

Валидными данными считаются цифры от 0 до 9, длина поля 2 символа в формате "mm".
Граничные зачения: от 01 до 12 включительно.

#### Поле "Год":
Валидными данными считаются цифры от 0 до 9, длина поля 2 символа в формате "yy". 
Граничные значения: от 26 до 31 включительно.

#### Поле "Владелец":

Валдидными данными считаются латинские буквы, символ "-" и пробел.
Длина поля от 2 символов до 21 символа включительно, учитывая символ "-" и пробел.

#### Поле CVC/CVV:

Валидными данными считаются цифры от 0 до 9, длина поля 3 символа.
Граничные значения от 000 до 999.

## Перечень автоматизируемых сценариев

### Позитивные сценарии

#### Сценарий 1. Оплата тура по карте

Предусловия:

1. В браузере открыта станица веб-сервиса по покупке тура "Путешествие дня Маракеш": http://localhost:8080/
2. Нажать кнопку "Купить"

####  1.1. Успешное проведение операции "Оплата по карте"

* В поле "Номер карты" введите валидный номер "4444 4444 4444 4441"
* В полях "Месяц", "Год", "Владелец", "CVC/CVV" введите валидные данные
* Нажмите кнопку "Продолжить"

**Ожидаемый результат:** Появляется сообщение: "Успешно Операция одобрена Банком".
В БД в таблице "payment_entity" сохраняется запись о совершении операции со статусом "APPROVED".
Ответ API имеет статус 200 и тело со статусом APPROVED.

#### 1.2. Отказ в проведении операции "Оплата по карте"

* В поле "Номер карты" введите валидный номер "4444 4444 4444 4442"
* В полях "Месяц", "Год", "Владелец", "CVC/CVV" введите валидные данные
* Нажмите кнопку "Продолжить"

**Ожидаемый результат:** Появляется сообщение: "Ошибка Ошибка! Банк отказал в проведении операции.".
В БД в таблице "credit_request_entity" сохраняется запись о совершении операции со статусом "DECLINED".
Ответ API имеет статус 200 и тело со статусом DECLINED.

<br>**Allure** - библиотека для генерации наглядных отчетов по результатам выполнения тестов. Показывает статистику прохождения, графическое представление проблем и детальную информацию о сбоях.

<br>**DBeaver** - Графический клиент для работы с базами данных, который позволяет управлять СУБД из одного интерфейса. Поддерживает MySQL, PostgreSQL и другие.

## Перечень и описание возможных рисков при автоматизации

1. Неверная настройка окружения. Тесты требуют стабильной и правильной настройки рабочей среды. Неправильная настройка окружения, зависимостей, баз данных или эмуляторов банковских сервисов могут привести к некорректным результатам тестирования или невозможности запуска тестов.
2. Некорректная работа приложений. Грубые ошибки при разработке приложений сервисов оплаты тура и симулятора банковского сервиса, что в свою очередь может привести к отказу запуска одного из приложений.
3. Сложности с поддержкой нескольких СУБД. Необходимо подстраивать тесты под конкретные СУБД, что увеличивает время автоматизирования и повышает риск ошибок.
