## Структура багов

Согласно структуре отчета Allure можно выделить следующие виды багов:

1. 61 багов или 51,6% приходятся на Api-тестирование, когда при отправке некорректных данных в формате json.
сервер возвращает код статуса "200" об успешном выполнении запроса, вместо кода "400", сообщающем о том, что 
сервер не будет обрабатывать запрос из-за некорректного формата данных. Из этого же числа можно выделить 15 багов, 
связанных с тем, что сервер не смог обработать запрос из-за внутренней ошибки и верул код статуса кодом "500".
2. 43 багов или 35,7% затрагивают проблему отображения информационных текстов и уведомлений на странице.
3. 16 багов или 12,7 % затрагивают проблему ввода данных в поля, которые должны оставаться пустыми при внесении 
невалидных значений: цифры, знаки, слова на невалидном языке.

## Реккомендации по устранению багов

1. Исправить формат приема данных сервером. При отправке невалидных данных через Api, сервер должен возвращать код "400".
2. Устранить внутерннюю ошибку сервера, вызывающую код "500". Сервер должен возвращать код "400".
3. Доработать валидацию поля "Владелец", согласно зафиксированных багов.
4. Устранить баги, связанные с отображением информационных сообщений и уведомлений на странице.
